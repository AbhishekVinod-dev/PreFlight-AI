# Stage 6: IBM BOB Integration Plan

## TL;DR
> **tl;dr**: This stage replaces the Antigravity-specific context system with **IBM BOB** tooling as required by the hackathon. IBM BOB uses `AGENTS.md` files (not `GEMINI.md`), `.bob/skills/` directories for reusable instruction sets, and three primary modes — **Plan mode** (architecture), **Code mode** (implementation), and **Ask mode** (exploration). The backend is split into two `AGENTS.md` files — one for Pair A (parsers + graph + specialist agents) and one for Pair B (orchestrator + decision engine + API layer). Both pairs must capture and upload **Bob task session summary screenshots** as hackathon submission evidence.

---

## 1. What IBM BOB Is (from the official guide)

IBM BOB is an AI-first IDE extension (VS Code-based) for the **IBM BOB 2.0 Hackathon**. Key facts:

| Aspect | Detail |
| :--- | :--- |
| **Primary interface** | BOB IDE (VS Code extension) |
| **Context file** | `AGENTS.md` (auto-generated by `/init` command) |
| **Skills location** | `.bob/skills/<skill-name>/SKILL.md` |
| **Modes** | Plan, Code, Ask, Agent |
| **CLI companion** | Bob Shell (optional, `bob` CLI command) |
| **Token budget** | Bobcoins — monitored at `bob.ibm.com` |
| **Submission requirement** | Must upload **Bob task session summary screenshots** to the repo |

## 2. Context File Convention Change

| Before (Antigravity) | After (IBM BOB) |
| :--- | :--- |
| `GEMINI.md` | `AGENTS.md` |
| `.agent/rules/*.md` | `.bob/skills/*.md` + `AGENTS.md` rules sections |
| Antigravity progressive disclosure | BOB `/init` auto-generation + manual AGENTS.md |

## 3. Files Generated in this Stage

| File | Pair | Purpose |
| :--- | :---: | :--- |
| `AGENTS.md` | Both | Root project context — overall architecture, shared contracts, data models |
| `backend/agents-pair-a/AGENTS.md` | A | Pair A-specific instructions (parsers, graph, specialist agents) |
| `backend/agents-pair-b/AGENTS.md` | B | Pair B-specific instructions (orchestrator, decision, API, remediation) |
| `.bob/skills/architecture-preflight.md` | Both | Reusable BOB skill for running pre-flight architecture checks |
| `.bob/skills/backend-coding-rules.md` | Both | Reusable BOB skill enforcing backend coding conventions |

## 4. BOB Workflow for Each Pair

### Pair A Workflow in BOB IDE

```
1. Open backend/ in BOB IDE
2. Run /init → BOB reads backend/agents-pair-a/AGENTS.md
3. Use Plan mode → design analyzer module interface
4. Use Code mode → implement Tree-sitter AST extractor
5. Use Ask mode → query the NetworkX graph topology rules
6. Repeat for each module: analyzers/, backend/graph/, backend/agents/*
7. Capture task session summary screenshots after each major task
```

### Pair B Workflow in BOB IDE

```
1. Open backend/ in BOB IDE
2. Run /init → BOB reads backend/agents-pair-b/AGENTS.md
3. Use Plan mode → design orchestrator dispatch pattern
4. Use Code mode → implement FastAPI routes + decision engine
5. Use Ask mode → inspect shared.py contracts before changes
6. Repeat for: orchestrator.py, decision/, evidence/, remediation/, api/
7. Capture task session summary screenshots after each major task
```

## 5. Submission Evidence Requirement

Per the IBM BOB hackathon guide, **both pairs must**:
1. Capture Bob IDE **task session summary screenshots** after each major implementation task.
2. Upload screenshots to the project repository (e.g., `docs/bob-sessions/pair-a/` and `docs/bob-sessions/pair-b/`).
3. Screenshots serve as evidence of BOB usage for hackathon judging.
